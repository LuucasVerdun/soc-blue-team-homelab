# Caso SOC — RDP Password Guessing seguido de Login Bem-Sucedido

## 1. Resumo executivo

Este caso documenta a implementação e validação de uma cadeia de detecção de autenticação RDP no SOC Home Lab utilizando Windows Server 2022, Windows Security Event Log, canais operacionais do Remote Desktop Services e Wazuh 4.14.7.

O objetivo foi detectar a sequência:

```text
Conexão RDP recebida
        ↓
Falha de autenticação
        ↓
Múltiplas falhas contra a mesma conta e mesmo IP
        ↓
Password Guessing
        ↓
Login RDP bem-sucedido
```

A cadeia foi validada com sucesso e culminou na Rule `100175`, Level 14, representando um login RDP bem-sucedido após password guessing.

Classificação:

```text
True Positive
Authorized Security Test
```

# 3. Preparação do Windows Server

O RDP foi habilitado com:

```powershell
Set-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server' -Name fDenyTSConnections -Value 0
```

As regras de firewall de Remote Desktop foram habilitadas:

```powershell
Get-NetFirewallRule | Where-Object {$_.DisplayName -match 'Remote Desktop|Área de Trabalho Remota'} | Enable-NetFirewallRule
```

O serviço `TermService` foi validado como `Running`.

A porta RDP foi validada a partir do Windows 10:

# 5. Telemetria observada

## Event ID 261 — conexão RDP recebida

Canal:

```text
Microsoft-Windows-TerminalServices-RemoteConnectionManager/Operational
```

Evento:

```text
Event ID: 261
Provider: Microsoft-Windows-TerminalServices-RemoteConnectionManager
Message: Listener RDP-Tcp received a connection
```

Esse evento não contém usuário nem endereço IP da autenticação.

## Event ID 4625 — falha de autenticação

Durante uma tentativa RDP com senha incorreta:

```text
Event ID: 4625
Logon Type: 3
Authentication Package: NTLM
User: SOC-RDP-TEST
Source IP: 192.168.100.20
Status: 0xC000006D
SubStatus: 0xC000006A
```

Interpretação:

```text
0xC000006D = Logon failure
0xC000006A = User exists, but password is incorrect
```

Com NLA, uma tentativa RDP com senha incorreta pode aparecer como `4625 / Logon Type 3`. Portanto, um `4625 Type 3` isolado não deve ser classificado automaticamente como falha RDP.

## Event ID 4624 — login RDP bem-sucedido

O login RDP válido foi registrado como:

```text
Event ID: 4624
Logon Type: 10
User: SOC-RDP-TEST
Source IP: 192.168.100.20
Authentication Package: Negotiate
```

Regra nativa do Wazuh:

```text
Rule ID: 92653
Level: 3
```

# 6. Troubleshooting da Rule 100160

Inicialmente, o Event ID 261 chegava ao manager e aparecia em:

```text
/var/ossec/logs/archives/archives.json
```

mas não gerava a Rule `100160`.

A árvore nativa mostrou:

```text
60000 - Group of Windows rules
    ↓
60009 - Windows informational event
```

Como o Event ID 261 possui:

```text
severityValue = INFORMATION
```

a Rule `100160` precisou ser filha da `60009`.

---

# 7. Rule 100160 — RDP Connection Received

```xml
<rule id="100160" level="5">
  <if_sid>60009</if_sid>
  <field name="win.system.providerName" type="pcre2">^Microsoft-Windows-TerminalServices-RemoteConnectionManager$</field>
  <field name="win.system.eventID">^261$</field>
  <description>SOC LAB: RDP connection received by Windows Remote Desktop listener.</description>
  <group>rdp,remote_access,soc_lab,</group>
  <mitre>
    <id>T1021.001</id>
  </mitre>
</rule>
```

MITRE:

```text
T1021.001 - Remote Desktop Protocol
```

Validação:

```text
2026-08-27T05:17:30.548+0000
Rule: 100160
Level: 5
Event ID: 261

```

# 8. Rule 100135 — senha incorreta para conta existente

```xml
<rule id="100135" level="6">
  <if_sid>60122</if_sid>
  <field name="win.eventdata.subStatus" type="pcre2">(?i)^0xc000006a$</field>
  <description>SOC LAB: Windows logon failure caused by incorrect password for an existing account.</description>
  <group>authentication_failed,password_failure,soc_lab,</group>
</rule>
```

# 9. Rule 100165 — Failed RDP Authentication

A regra correlaciona:

```text

+
100135 - senha incorreta
```

em uma janela de 10 segundos.

```xml
<rule id="100165" level="7" timeframe="10">
  <if_sid>100135</if_sid>
  <if_matched_sid>100160</if_matched_sid>
  <description>SOC LAB: Failed Windows authentication associated with a recent RDP connection.</description>
  <group>authentication_failed,rdp,remote_access,soc_lab,</group>
  <mitre>
    <id>T1021.001</id>
    <id>T1110.001</id>
  </mitre>
</rule>
```

# 10. Rule 100170 — RDP Password Guessing

Configuração validada:

```xml
<rule id="100170" level="12" frequency="4" timeframe="60">
  <if_matched_sid>100165</if_matched_sid>
  <same_field>win.eventdata.targetUserName</same_field>
  <same_field>win.eventdata.ipAddress</same_field>
  <description>SOC LAB: Repeated RDP authentication failures against the same Windows account from the same source IP.</description>
  <group>authentication_failed,rdp,brute_force,password_guessing,remote_access,soc_lab,</group>
  <mitre>
    <id>T1021.001</id>
    <id>T1110.001</id>
  </mitre>
</rule>
```

# 16. Prioridade analítica

```text
100160 - Level 5  - conexão RDP recebida
100165 - Level 7  - falha RDP contextualizada
100170 - Level 12 - RDP Password Guessing
100175 - Level 14 - sucesso RDP após Password Guessing
```

A Rule `100175` representa o cenário de maior prioridade porque combina repetidas tentativas de senha com um acesso remoto interativo bem-sucedido logo em seguida.

---

# 17. Perspectiva de triagem SOC

Ao receber a Rule `100175`, o analista deve verificar:

```text
1. usuário afetado
2. IP de origem
3. quantidade e frequência das falhas anteriores
4. horário do primeiro e último evento
5. conta local ou de domínio
6. contexto do endpoint de origem
7. atividade pós-login
8. processos criados após a sessão RDP
9. comandos executados
10. persistência ou movimentação lateral subsequente
```

No laboratório:

```text
User: SOC-RDP-TEST
Source IP: 192.168.100.20
Destination: 192.168.100.30
Classification: True Positive
Context: Authorized Security Test
```

# 18. Limitação conhecida

O Event ID 261 não fornece:

```text
targetUserName
ipAddress
```

Por isso a Rule `100165` utiliza correlação temporal curta entre a conexão RDP e a falha de autenticação.

Em ambientes com alto volume de conexões simultâneas, pode ser necessário enriquecer a detecção com telemetria adicional de firewall, rede, Sysmon, RdpCoreTS ou EDR.

# 19. Observação sobre wazuh-logtest

Durante o troubleshooting, eventos extraídos de:

```text
/var/ossec/logs/archives/archives.json
```

e reenviados ao `wazuh-logtest` foram decodificados como:

```text
json
```

em vez de:

```text
windows_eventchannel
```

Por isso, o replay de `full_log` não reproduziu integralmente o pipeline real de produção.

A validação definitiva foi feita com eventos reais enviados pelo Wazuh Agent.
